# Text sidecar contract

The text sidecar tokenizes Japanese EPUB text for Kavita's dictionary popup. It isn't in this repo. It's built from the shimen repo as that repo's `sidecar` Docker target, so it runs shimen's own tokenizer, word rules and lexicon. These files are what Kavita and the sidecar agree on for `POST /tokenize`, and `GET /health` answers `{"version": "..."}`.

`tokenize-request.schema.json` and `tokenize-response.schema.json` are the request and response. Each token is the array `[s, e, w, r, sub]`, where `s` and `e` are UTF-16 offsets into the block's text, `w` indexes `words` or is null, `r` is the occurrence's hiragana reading or null, and `sub` is null or the compound's parts as `[s, e, w, r]`. From `sidecar=2` a token can also be two neighbours joined into a dictionary headword, with the two as its parts, and each block has `phrases`, an array of `[s, e, w]` spans over two or more whole tokens that together form an expression. A `sidecar=1` response has no `phrases`, and Kavita reads that as none.

`sample-request.json` and `sample-response.json` are copied from the shimen repo's `backend/shimen/sidecar/contract/`, and so are the two schemas. The response is what the real sidecar returns for the request. Kavita's tests deserialize it, so copy all four files again whenever the sidecar's contract changes. The `phrases` and the について word in `sample-response.json` were written by hand in Kavita before shimen's own sample had them, so copy shimen's files over them once it does.
